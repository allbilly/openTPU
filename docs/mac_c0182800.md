# c0182800 Mac runtime

Build `c0182800` repairs the CH0 shared read-response bus and registers the host
reset source. It provides JTAG USER2 and PCIe memory/control, with a 250 MHz
host clock independent of PCIe. Compute is 100 MHz, DDR800, capacity 4 GiB.
CH0 uses physical lanes `0,1,2,3,4,5,8,7` without ECC; CH1 retains ECC.

`df2521d80de1d69ea4ca758821dc67a814b95d67ac851b78727c9154a3104bf2`.

Exact packet/CRC, routing, timing, pin, pad and CDC review passed. All 1,993
non-info CDC rows are accounted for under the recorded operating contracts.
The original 62 bus-skew constraints and ten additional CSR Gray-pointer
assertions pass. Setup slack is +0.049 ns; hold slack is +0.013 ns.
External DDR pad timing and physical PCIe/reset reliability remain unqualified.

Local JTAG SRAM loading, live image identity and CH0 calibration passed with
PCIe absent. Full-memory zero initialization, the 1,371-instruction fetch check
(65 exact words, 1,496 cycles) and int8 matmul (32 exact words, 333 cycles) passed.
TinyStories passed: all 28,909,056 uploaded bytes and their SHA256 matched, all
15 program readback/load checks passed, and eight tokens matched the ISA exactly.
Calibration stayed unchanged and final ECC guards passed. See the small
[local validation receipt](../runtime/c0182800/local-validation.json).
Permanent c0182800 programming, independent verification and JTAG-requested
flash boot passed on October 18. A fresh live identity reported c0182800,
100 MHz / DDR800 / 4 GiB, with CH1 automatic startup ready and CH0 awaiting
this helper. JTAG was released. On the Mac, LFM2.5-230M and Qwen3.5-2B INT8

Qwen occupied 94.2% of 4 GiB and measured 11.51 GB/s while decoding, with

[Mac benchmark record](data/spare_pcie_benchmark_20261018.json) preserves both

## Run on the Mac

Use this runtime after the exact c0182800 image has been permanently programmed
and booted. A power cycle restores fresh CH1-only startup calibration; the
matching helper then calibrates CH0 while preserving CH1. Runtime identity
checks reject other images. Coordinate all writers during calibration/BIST.

Obtain the published runtime files on branch `ypcb/dual-channel-4gb` through
ordinary Git. New local benchmark records/tools require an authorized commit
and push before another host can retrieve them.
No bitstream, generated netlist, Vivado installation or model weights are needed
in Git for an already flashed card. Keep the local LFM2.5-230M checkpoint.

```bash
git fetch origin
git switch ypcb/dual-channel-4gb
git pull --ff-only
export SPARE_PYTHON=build/chestnut-lfm/venv/bin/python
export SPARE_MODEL=models/LFM2.5-230M
export SPARE_OUT="build/mac-c0182800-$(date -u +%Y%m%dT%H%M%SZ)"
bash tools/mac_spare_c0182800.sh preflight
bash tools/mac_spare_c0182800.sh lfm
```

The preflight opens no device. The LFM command checks live identity, calibrates
CH0, initializes memory, compares matmul and runs LFM against the ISA reference.
Every program must read back exactly before the instruction-memory load is
requested. A mismatch preserves expected/actual bytes and withholds execution.

Keep all receipts under `SPARE_OUT`, including failures. Use a fresh output
directory for another complete run. After successful calibration/testing in the
same configuration, the bandwidth command reuses that output directory:

```bash
bash tools/mac_spare_c0182800.sh bandwidth
```

JTAG transfer timing does not establish PCIe or accelerator bandwidth. Local
TinyStories is an additional check, separate from the completed Mac acceptance.

## Qwen3.5-2B near-capacity benchmark

After a successful `lfm` run above, leave the same card configuration powered
and use its existing calibration and initialization receipts. Choose a fresh
benchmark output directory:

```bash
"$SPARE_PYTHON" tools/benchmark_spare_c0182800.py \
  --calibration-receipt "$SPARE_OUT/calibration/manifest.json" \
  --initialization-receipt "$SPARE_OUT/lfm/manifest.json" \
  --out build/mac-c0182800-qwen35-2b-1
```

The default checkpoint is `models/Qwen3.5-2B`; `--model /path/to/checkpoint`
overrides it. Retain its `download-metadata.json` with the pinned revision and
hashes, as produced by `tools/chestnut_checkpoints.py`. The helper checks the
exact image and live calibration, complete zero-initialization coverage and
the memory initialization marker before uploading. A power cycle invalidates
the earlier calibration; run the fresh-boot LFM procedure again in that case.
No other process may use the card during these commands.

The benchmark uses INT8 weights, resident decode and a 4096-token cache,
allocating 94.2% of memory. It uploads the image in 4 MiB host chunks, compares
four boundary samples and checks every program readback before IMEM loading.
Eight chat tokens are compared with fresh ISA, then 512 Austen prompt tokens
and 32 greedy decode steps are timed. `decode.device_dram_gb_s` is aggregate
64-byte read/write counter traffic divided by device running time, excluding
host idle time. Wall rates include program verification and full-logit USB
readback. Initialization, model packing/upload and the separate ISA check are
outside those timings. This command does not program flash or recalibrate.

The benchmark record refers to the original observed runner and local receipt
hashes. The portable CLI above was extracted afterward; its offline checks do
not constitute another physical benchmark run. Keep the new `manifest.json`
and per-program receipts, including failures. Full payload and repeatability
qualification remain separate from this one measured workload.

## Recorded build inputs

This image's ABI2 reads at `0x60` and `0x64` report the CH0 lane map and ECC
mask. Writes at those addresses still set ARG0 and ARG1. The supplied LLM
runner writes arguments and does not read them back; diagnostic tools must
interpret these reads as identity fields. ARG2 through ARG7 retain readback.

The small [runtime identity](../runtime/c0182800/runtime.json) pins the full
reviewed manifest and required calibration/configuration files. Its review
summaries bind the omitted large artifacts by checksum. Live registers identify
the connected image; they do not cryptographically rehash permanent flash.

The local immutable source preparation is
`build/fedora-vivado/spare-shared-dual-c0182800-20261018`, manifest SHA256
`3bf72954ddfd0e0878fe0f7afab26d60ce9d35af6c4c457050de7bf5c0f1066e`.
Its `frozen-tools/run-shared-successor.py` records the full native build command.
Rebuild on the build host from a fresh preparation with those same parameters,
shared adapter, registered reset and both runtime interfaces; preserve completed
output directories. A rebuilt artifact needs its own checksum, exact review and
SRAM checks. The recorded source preparation is not required for Mac runtime.
