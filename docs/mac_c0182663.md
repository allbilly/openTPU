4 GiB, CH0 lanes `[0,1,2,3,4,5,8,7]`, CH1 ECC enabled and both JTAG/PCIe
runtime interfaces. The exact bitstream is
`bitstreams/spare-dual-host-4gb-c0182663/otpu.bit`, SHA256

## Prepared runtime procedure

This guide targets a card already configured with c0182663. A temporary JTAG
SRAM load is lost on power cycling; check the booted image before moving to
Mac inference. Chestnut supplies PCIe access. New image programming requires
the separate JTAG connection and the exact reviewed programming artifact.
Large `.bit`/`.mcs` files remain outside Git.

Both channels calibrate automatically using embedded firmware **c0172668**,
with reset-default configuration `0x103`. The matching observer records the
eight-lane CH0 and nine-lane CH1 results and checks their live readiness and
unchanged mailbox/phase state. It performs no host firmware upload or startup
control writes. Calibration and whole-memory initialization are separate.

The small files under `runtime/c0182663` support an already configured card.
Runtime use requires no bitstream or generated netlist transfer. The runtime
metadata pins the original image manifest and retained files. Omitted source
and CPU-model documents retain recorded review hashes and selected fields;
their omitted bytes are not reverified on the Mac. Live registers establish
the reported image identity, rather than cryptographically attesting flash.
Programming, local SRAM acceptance and Mac workload acceptance are separate
results; adding these files does not change the card's configured image.

After the matching host/runtime files have been published, use the checkout
root, select the existing Python environment and local LFM2
checkpoint, then choose a fresh results directory:

```bash
export SPARE_PYTHON="${SPARE_PYTHON:-python3}"
export SPARE_MODEL=models/LFM2.5-230M
export SPARE_OUT="build/mac-c0182663-lfm-$(date -u +%Y%m%dT%H%M%SZ)"
bash tools/mac_spare_c0182663.sh preflight
bash tools/mac_spare_c0182663.sh lfm
```

`preflight` validates runtime/startup bindings without opening Chestnut.
`lfm` first reads live identity, observes automatic startup, initializes all
4 GiB and verifies zeros, then compares matmul and LFM2 against the ISA.
Every program must read back exactly before its IMEM load. Keep every receipt,
including a failed or interrupted run, under the selected `SPARE_OUT`.

| Stage | Required evidence |
| --- | --- |
| Identity | c0182663, 148837 kHz, DDR1066 and the exact lane/ECC/interface profile |
| Startup | Firmware c0172668, configuration `0x103`, both channels ready, eight/nine decoded lanes and clean ECC counters |
| Initialization | 2,048 complete 4 MiB operations: 4 GiB written and 4 GiB zero-verified |
| Matmul | All 32 output words match ISA |
| LFM | Exact ISA tokens, exact program readbacks, unchanged calibration and clean ECC counters |

Automatic calibration does not remove the initializer's existing 200 ms
pauses: 2,048 pauses total 409.6 seconds, plus memory/host time. This image's
runtime keeps that policy. A successful JTAG TinyStories test is an initial
shared compute/DDR screen; PCIe/Chestnut and the larger LFM memory/program paths
still need their own acceptance results.

For identity alone, use the `identity` wrapper stage with a separate fresh
`SPARE_OUT`. The `quick` stage observes startup and checks bounded DMA and
masked writes; it does not qualify the entire memory range. After successful
LFM integration in the same powered configuration, an optional native-read
measurement can reuse its startup receipt:

```bash
bash tools/mac_spare_c0182663.sh bandwidth
```

Device-counter throughput, serial/USB transfer throughput and LLM wall decode
are separate measurements. A new power/configuration epoch requires fresh
startup observation and initialization. Use a fresh output directory for each
new full run, and let an active test finish before changing its host sources.
