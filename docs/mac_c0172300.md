# Mac inference: c0172300, 4 GiB spare-lane image

This procedure uses the card already programmed in permanent flash. The Git
checkout supplies the matching runtime files; no archive, bitstream, generated
netlist, Vivado installation or separate `ypcb` checkout is needed on the Mac.

The runtime metadata records the original offline review and later programming

## Run LFM2

Power off the card before moving it to the Mac. Connect its existing compatible
12 V supply and Chestnut, then power on. Use the same working Python environment
and local LFM2 checkpoint as the previous Mac run. The environment needs NumPy,
PyTorch, Transformers compatible with that checkpoint, and safetensors; Chestnut
uses `libusb` (`brew install libusb` if absent). Python 3.12 is suitable.

The active branch is `ypcb/dual-channel-4gb`, renamed locally from
`ypcb/ch1-bringup-local` to reflect the dual-channel spare-lane work. After this
branch has been published, from the Mac checkout:

```bash
git fetch origin
git switch ypcb/dual-channel-4gb
git pull --ff-only
export SPARE_PYTHON=/path/to/working/python
export SPARE_MODEL=/path/to/LFM2/checkpoint
export SPARE_OUT=build/mac-c0172300-lfm-1
bash tools/mac_spare_c0172300.sh preflight
bash tools/mac_spare_c0172300.sh lfm
```

Replace both `/path/to/` values with local paths. `preflight` validates the small
files and firmware without opening the device. `lfm` checks live identity,
calibrates CH0 while retaining CH1 calibration, initializes both channels for
valid memory/ECC contents, compares matmul with the ISA simulator, then compares
LFM2 output tokens with the ISA reference. It does not add a standalone RAM soak.
Initialization and inference overwrite memory; do not run another card client.

Use a fresh `SPARE_OUT` for each new configuration. The calibration helper needs
a fresh boot/configuration with no prior native traffic. After failure, retain
the manifests rather than automatically retrying calibration. Power-cycle before
starting another fresh calibration attempt. None of these commands programs the
FPGA or writes flash.

## Measure the bandwidth correction

After the successful `lfm` run, keep the card powered with the same configuration
and retain `SPARE_OUT`:

```bash
bash tools/mac_spare_c0172300.sh bandwidth
```

This runs three 64 MiB native-read streams. It checks instruction/traffic
counters and the final 16 KiB payload, and reports device-counter GB/s separately
from the host run-call time, which includes USB overhead. It overwrites program
and output memory; reload the model before another inference workload. It does
not establish full-range correctness or guarantee twice the CH1-only bandwidth.

Return the JSON manifests under `$SPARE_OUT`, including failures. The key files
are `identity/manifest.json`, `calibration/manifest.json`, `lfm/manifest.json` and
`bandwidth/manifest.json`. The LFM manifest includes matmul and token comparisons.

## Runtime file provenance

[`runtime.json`](../runtime/c0172300/runtime.json) pins the small file inventory,
configuration and review summaries. `reviewed-image.json` is the unchanged
original image manifest; its `hardware_accessed: false` describes the earlier
offline packaging stage. The separate programming summary records the later
flash operation. The small `selfcal.bin` is required CH0 calibration firmware,
not a configuration bitstream.

To reproduce this export on the build host, with the original fully reviewed
image package and successful programming receipt available locally:

```bash
python3 tools/export_spare_c0172300_runtime.py \
  --package bitstreams/spare-pcie-4gb-pipeline-ddr800 \
  --flash-receipt build/fedora-vivado/spare-pipeline-c0172300-flash-20261017/manifest.json \
  --out build/c0172300-runtime-export
```

The exporter verifies the original package, copies only the allowed small files
and prints the runtime manifest digest. A changed export requires review and an
explicit update of the digest pinned in `opentpu/host/spare_c0172300.py`.
